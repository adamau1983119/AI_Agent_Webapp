## 一、核心體驗目標（完整體驗）

### 1.1 一句話

使用者從 **我的頻道 → 建立頻道** 進入後，**主畫面即 AI 助手**（對話、輸入、結構化動作），**無需先點「開啟助手」**；在助手語境內完成 **意圖 → 來源 → 命名／描述 → 送出前確認 → 建立結果**。

### 1.2 體驗原則（完整版）

| 原則 | 說明 |
|------|------|
| **單一主舞台** | 全幅或語意上的「唯一核心」為助手，避免表單與助手搶主權。 |
| **零門檻喚起** | 助手預設開啟、常駐；主流程不依「發現按鈕」才能開始。 |
| **閉環完成** | 類別、地區、主題／關鍵字、RSS 取捨（≤10）、命名與描述、建立，皆可於助手內完成或明確跳轉至助手內子區塊。 |
| **表單弱化** | 結構化資料存在於 state／API；畫面以 **摘要卡、可展開編輯、進階抽屜** 為主，傳統三步大表單為備援。 |
| **長尾不阻塞** | 自然語言、冷門槽位：澄清問題、替代路徑（描述、貼 URL、手動），敘事仍歸助手。 |
| **可信任** | 寫入 `POST /channels` 前：**可視、可改、可還原**；關鍵變更有摘要或差異提示。 |
| **可觀測** | 步驟完成、放棄、錯誤、建立成功等事件，預留分析／稽核欄位（實作階段再接）。 |

### 1.3 與 §E 的關係

- **§E（Phase A）**：已凍結 **L0～L4** 與 **文件階段 DoD**、Phase B～D 邊界。  
- **本檔第一節**：把 **核心體驗目標** 寫成可對齊全專案的敘述，供 **一＋二** 定稿與驗收引用。

## 二、資訊架構（L0～L5）

### 2.1 層級定義

| 層級 | 職責 | 使用者可見（目標） |
|:----:|------|-------------------|
| **L0** | 導覽、語言、權限 | 標題、返回、未登入導向；全頁錯誤時仍有出口。 |
| **L1** | 主舞台（助手） | 訊息流、輸入、**結構化捷徑**（類別、地區、主題、RSS 動作）、必要時 **內嵌預覽**（來源名、網域、已選 n/10）。 |
| **L2** | 進度與可完成性 | 頂部進度 **或** 助手內「目前已具備／尚缺」— 與「可建立」條件掛鉤。 |
| **L3** | 送出前確認 | **摘要卡**：名稱、描述、已選 RSS、類別／地區／關鍵字；**建立** 與 **返回修改** 同層級。 |
| **L4** | 進階／脫困 | 完整表單、匯入草稿、說明／客服連結；**離線、429、AI 失敗** 的明確路徑與重試。 |
| **L5（可選）** | 草稿與延續 | 裝置或伺服器 **草稿自動存**、跨裝置續作、命名／RSS **變更歷史**（完整願景能力，實作可分期）。 |

### 2.2 與現有三步驟的對應（邏輯非畫面）

| 業務步驟 | 在助手主導下的語意 |
|----------|-------------------|
| Step 1 | L1 內完成「類別／地區／一句話或關鍵字」蒐集。 |
| Step 2 | L1＋L3 內完成「候選池／已選 ≤10／搜尋／貼 URL 驗證」。 |
| Step 3 | L1＋L3 內完成「命名／描述（含 #32/#33 建議）」與 **建立**。 |

### 2.3 定稿順序建議（供決策）

**一（核心體驗目標）與二（本節 IA）宜先對齊**，再展開第三、四節的工程細節；避免先做後端大功能卻與主畫面敘事衝突。

## 三、前端架構（完整）

### 3.1 路由與模式

| 項目 | 說明 |
|------|------|
| **主路由** | `/channels/create`（與 [專案完整架構表.md](../專案完整架構表.md) 一致）。 |
| **可選擴充** | 草稿深連結 `?draft=`、僅進階模式之管理或支援入口（權限控管）。 |
| **版面模式** | `assistant-first` 為預設；`legacy-form` 僅作 **L4 進階** 或特殊角色。 |

### 3.2 狀態單一真相（建議拆分）

| 狀態域 | 內容 |
|--------|------|
| **對話** | 訊息列表、回合、loading、錯誤、重試計數。 |
| **頻道草稿** | `category`、`region`、`customKeywords`、`selected_feeds`（或等價 URL 集合）、`name`、`description`。 |
| **助手業務** | `exclude_urls`、已展示推薦 URL、`wizard-options` 步驟、澄清問句、assist 建議命名快取。 |

### 3.3 元件邊界（邏輯模組名，實作可映射至 `CreateChannel.tsx` 或子元件）

| 模組 | 職責 |
|------|------|
| `AssistantShell` | 主舞台容器、版面主從。 |
| `MessageList` / `Composer` | 對話與輸入。 |
| `ActionChips` 或 `OptionGrid` | 類別、地區、RSS 相關結構化動作。 |
| `SourcePreview` | 單筆／列表來源預覽。 |
| `SummaryPanel` | L3 送出前摘要。 |
| `AdvancedDrawer` | L4 進階表單或手動編輯。 |
| `StepIndicator` | L2 進度（若採頂部條）。 |

### 3.4 API 客戶端對應（現有能力為基線，完整願景可擴）

| 前端需求 | 後端端點（概念） |
|----------|------------------|
| 精靈結構化選項 | `POST .../assist/wizard-options` |
| 意圖與推薦、命名建議 | `POST .../assist` |
| 預設池 | `GET .../defaults/rss-sources` |
| 白名單搜尋 | `GET .../feeds/search` |
| 貼 URL | `POST .../feeds/validate` |
| 建立頻道 | `POST .../channels` |

### 3.5 橫切關注點

- **i18n**：所有使用者可見字串 → `frontend/src/i18n/index.ts`（zh-TW／en／ja），禁止硬編碼（品牌例外依 README）。  
- **data-testid**：依 [按鈕測試ID架構表.md](../按鈕測試ID架構表.md)。  
- **無障礙**：焦點順序、步驟語意、鍵盤可操作。  
- **錯誤**：HTTP 429 等依 `detail.code` 對應 i18n（與現行策略對齊）。

## 四、後端與領域（完整）

### 4.1 API 與服務邊界（在現有 `channels` 路由器上擴充願景）

| 能力 | 說明（完整願景） |
|------|------------------|
| **意圖與對話** | `assist` 作為中樞；可多輪槽位、澄清策略、輸出安全（注入／過濾）。 |
| **結構化選項** | `wizard-options` 與 assist 並行，降低純 NL 不穩定時的摩擦。 |
| **RSS 取得** | 預設池、白名單搜尋、貼 URL 驗證；**擴充願景**：受控外部檢索、索引／RAG、預算與全局限流。 |
| **命名／描述** | #32/#33 擴充願景：多版本建議、語氣／平台分套、使用者選版再微調。 |
| **建立** | `POST /channels` 維持契約；擴充：**草稿 CRUD**、建立前重複名稱檢查、欄位審計。 |

### 4.2 安全與濫用

| 項目 | 說明 |
|------|------|
| **SSRF／probe** | 陌生 URL 必經與現有 `feed_url_probe` 一致或更嚴格之 **政策引擎**（網域聲譽、允許清單、速率）。 |
| **限流** | per-IP／per-user；多實例時 **共享儲存**（如 Redis）與儀表（完整願景）。 |
| **認證** | 既有 JWT；敏感操作可加重驗證（願景層級）。 |

### 4.3 資料與持久化

| 項目 | 說明 |
|------|------|
| **正式頻道** | Mongo `channels`，含 `selected_feeds` 等（與架構表 ① 對齊）。 |
| **草稿（L5）** | 獨立集合或使用者子文件；與建立 API 分離，避免誤寫正式資料。 |
| **收集行為** | `get_rss_sources_for_channel` 與使用者選取之 Layer 邏輯（架構表已有，完整願景下文件化策略分支）。 |

### 4.4 稽核與營運（完整願景）

- 建立頻道事件：**誰、何時、摘要欄位、所用外部 URL 類型**（合規／除錯）。  
- 功能開關與漸進放量（例如助手主導模式）：**部署策略**另見 release 文件（本檔僅列需求位）。**細部**併入 **第六章** 與檢查清單 **I**。

## 五、資料與生命週期（完整）

> **計劃**：本章為 **資料面全集**；**實作、對照程式與策略文件**預設延至 **測試階段** 與檢查清單 **H** 逐項補齊（見 [channel_create_new_scheme_checklist.md](./channel_create_new_scheme_checklist.md) §H）。

### 5.1 正式頻道與草稿

| 項目 | 說明 |
|------|------|
| **Mongo `channels`** | **正式頻道**之權威來源；含 `selected_feeds`、名稱、描述等（與 `專案完整架構表.md` ① 及現有 API 契約對齊）。 |
| **草稿** | 可另立 **`channel_drafts` 集合** 或 **`users.drafts`**（嵌套／子文件）；與 **`POST /channels` 正式建立** 分離，避免誤寫正式資料與誤觸收集。 |

### 5.2 選取 RSS（`selected_feeds`）

| 項目 | 說明 |
|------|------|
| **正規化** | URL trim、僅 https、長度與格式與後端 Pydantic 一致。 |
| **去重** | 同一頻道內 URL **唯一**；合併候選池時語意明確。 |
| **上限** | **≤10**（與現行契約一致）。 |
| **建立後與 collector** | 選取結果與 **`get_rss_sources_for_channel`／Layer1／Layer2** 行為 **一致**；完整分支策略可擴寫為獨立 **策略文件**（由架構表 ①② 延伸）。 |

### 5.3 刪除／改名／再編輯（與「建立」對稱）

| 項目 | 說明 |
|------|------|
| **完整 CRUD** | 建立之外，**讀取、更新、刪除** 頻道與其 `selected_feeds` 等欄位行為對稱、可稽核。 |
| **同步** | 前端「我的頻道」列表／詳情與後端 **最終一致**；快取或樂觀更新若有，需定失效條件（測試階段驗證）。 |

## 六、測試、發布、營運（完整）

> **計劃**：本章為 **品質與釋出全集**；**E2E、開關、ADR 等**預設延至 **測試階段** 與檢查清單 **I** 逐項補齊。

### 6.1 測試（完整）

| 類型 | 說明 |
|------|------|
| **E2E** | **僅透過助手主路**完成建立頻道（含送出前確認）；與「先開表單」路徑對照迴歸。 |
| **無障礙** | 焦點、語意、鍵盤可操作（與 Phase C／清單 C 呼應，此處為 **全頁／全流** 收口）。 |
| **多語** | zh-TW／en／ja 覆蓋建立流程 **全部** 新增文案。 |
| **429** | validate／search／assist 等限流與 `detail.code` 行為與前端 i18n **端到端**。 |
| **離線** | 斷網、逾時、後端不可用時 **可理解** 狀態與重試／降級（不白屏、不無限 spinner）。 |
| **大列表效能** | 候選池／訊息列表 **大量資料** 時捲動與互動（訂定門檻於測試計劃）。 |

### 6.2 發布（完整）

| 項目 | 說明 |
|------|------|
| **功能開關** | 例如 **`assistant_first_create_channel`**（名稱可依環境變數實作調整）：預設關／灰度開／全開策略文件化。 |
| **漸進放量** | 百分比或 allowlist；與監控儀表連動（可選）。 |
| **回滾策略** | 開關關閉或部署前一版之 **步驟與責任人** 明文化。 |

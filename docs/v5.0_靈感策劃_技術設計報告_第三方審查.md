## 1. 設計邏輯與架構

### 1.1 核心設計理念

**目標**：將現有的「簡單搜尋」功能升級為「專業網紅靈感助手」，提供深度內容生成和智慧互動能力。

**設計原則**：
1. **最大化重用現有服務**：避免重複開發，降低維護成本
2. **AI 驅動的智慧互動**：100% AI 動態生成，不使用預設模板
3. **資料真實性保證**：AI 驗證來源，確保資訊準確性
4. **個人化體驗**：AI 學習用戶偏好，提供個性化服務

### 1.3 核心流程設計

#### 流程 1：智慧助手模式（完整流程）

```
1. 用戶輸入主題
   ↓
2. 檢查用戶偏好（資料庫查詢，零 AI 成本）
   ↓
3. AI 動態生成問題（1 次 AI 調用，300-500 Token）
   - 使用 AI 分析主題
   - 生成最多 3 個針對性問題
   - 提供快速選擇選項
   ↓
4. 用戶回答問題
   ↓
5. 多來源搜尋（Google Custom Search API，零 AI 成本）
   - 官方網站
   - 媒體報導
   - 維基百科
   - 餐飲平台
   ↓
6. AI 驗證來源（1 次 AI 調用，500-800 Token）
   - 檢查資訊真實性
   - 評估來源可信度
   - 標註驗證狀態
   ↓
7. 生成內容（1 次 AI 調用，2000-3000 Token）
   - 根據用戶選擇的格式（影片講稿/文章/貼文/大綱）
   - 應用用戶偏好（語氣、風格）
   - 包含指定模組（地址、歷史背景等）
   ↓
8. AI 學習偏好（1 次 AI 調用，可選，200-300 Token）
   - 分析用戶互動模式
   - 更新用戶偏好
   ↓
9. 輸出結果
   - 內容預覽
   - 驗證狀態標籤
   - 來源連結
   - 靈感拓展建議
```

**Token 成本**：
- **標準流程**：3 次 AI 調用 = 2800-4300 Token
- **包含學習**：4 次 AI 調用 = 3000-4600 Token

### 1.4 設計決策說明

#### 決策 1：100% AI 動態生成問題

**原因**：
- 客戶要求：不使用任何預設模板
- 靈活性最高：完全根據主題個性化
- 用戶體驗最佳：問題更精準、更有針對性

**代價**：
- 每次消耗 300-500 Token
- 響應時間稍長（約 2-3 秒）

#### 決策 2：AI 驗證來源

**原因**：
- 客戶要求：必須使用 AI 驗證，不使用邏輯判斷
- 準確性更高：AI 能理解語義，判斷更準確
- 可解釋性：提供驗證理由

**代價**：
- 每次消耗 500-800 Token
- 成本較高

#### 決策 3：重用現有服務

**原因**：
- 降低開發成本
- 減少維護負擔
- 保持系統一致性

**重用服務**：
- Google Custom Search API（現有）
- AI 服務工廠（現有）
- Prompt 模板系統（現有）

## 5. 資料庫設計

### 5.1 新增 Collections

#### Collection 1: `inspiration_sessions`

**用途**：儲存對話會話和偏好

**結構**：
```javascript
{
  _id: ObjectId,
  user_id: ObjectId,  // 關聯 users collection
  session_id: String,  // 會話 ID
  topic: String,  // 主題
  preferences: {
    format: String,  // 'video_script' | 'article' | 'post' | 'outline'
    tone: String,    // 'casual' | 'professional' | 'storytelling'
    region: String,  // 地區
    language: String  // 'zh-TW' | 'en' | 'ja'
  },
  messages: [
    {
      role: String,  // 'user' | 'assistant'
      content: String,
      type: String,  // 'question' | 'answer' | 'content'
      timestamp: Date
    }
  ],
  created_at: Date,
  updated_at: Date,
  completed_at: Date
}
```

**索引**：
```javascript
db.inspiration_sessions.createIndex({ user_id: 1, created_at: -1 });
db.inspiration_sessions.createIndex({ session_id: 1 });
```

#### Collection 2: `user_inspiration_preferences`

**用途**：儲存用戶偏好（已更新：加入過期和確認機制）

**結構**：
```javascript
{
  _id: ObjectId,
  user_id: ObjectId,  // 關聯 users collection
  preferences: {
    // 高頻偏好（自動套用）
    default_format: String,
    default_tone: String,
    preferred_regions: [String],
    preferred_languages: [String],
    
    // 中頻偏好（使用 3 次後確認）
    output_length: String,  // 'short' | 'medium' | 'long'
    detail_depth: String,   // 'brief' | 'moderate' | 'detailed'
    
    // 低頻偏好（立即確認）
    module_preferences: [String],  // 用戶偏好的模組
    special_requirements: String
  },
  usage_stats: {
    total_sessions: Number,
    most_used_format: String,
    most_used_tone: String,
    last_used_at: Date,  // 最後使用時間（用於過期檢查）
    last_updated: Date
  },
  // 過期管理（新增）
  status: String,  // 'active' | 'stale' | 'expired'
  stale_since: Date,  // 標記為過時的時間
  confirmation_pending: [  // 待確認的偏好（新增）
    {
      preference_type: String,
      suggested_value: String,
      usage_count: Number,
      suggested_at: Date
    }
  ],
  created_at: Date,
  updated_at: Date
}
```

**索引**：
```javascript
db.user_inspiration_preferences.createIndex({ user_id: 1 }, { unique: true });
db.user_inspiration_preferences.createIndex({ "usage_stats.last_used_at": 1 });  // 用於過期檢查
db.user_inspiration_preferences.createIndex({ status: 1 });  // 用於查詢過時偏好
```

## 7. 風險評估

### 7.1 技術風險

| 風險 | 影響 | 機率 | 緩解措施 |
|------|:----:|:----:|---------|

| **Google API 配額用盡** | 中 | 低 | 實現 AI 生成備選方案（已實現） |

### 7.2 業務風險

|------|:----:|:----:|---------|

#### 問題 1：來源驗證策略

**審查意見**：
- 文件中設計為「AI 驗證來源」，但是否應該同時保留邏輯判斷或至少兩個來源交叉比對？
- 如果 AI 判斷錯誤，是否有 fallback 機制？

**回應與解決方案**：

✅ **建議採納**：實現多層驗證機制

**設計調整**：
1. **第一層：邏輯判斷（零成本）**
   - 檢查來源數量（至少 2 個）
   - 檢查來源類型（官方網站 > 媒體 > 維基百科）
   - 檢查來源 URL 格式

2. **第二層：AI 驗證（必須）**
   - AI 分析資訊真實性
   - AI 評估來源可信度
   - AI 提供驗證理由

3. **第三層：交叉比對（必須）**
   - 至少 2 個獨立來源確認同一資訊
   - 如果只有 1 個來源，標註「未驗證」

**Fallback 機制**：
- 如果 AI 驗證失敗，使用邏輯判斷結果
- 如果邏輯判斷也失敗，標註「未驗證」，提醒用戶自行確認

**實現方式**：
```python
async def verify_sources(
    self, 
    information: str,
    sources: List[Dict[str, Any]]
) -> Dict[str, Any]:
    # 第一層：邏輯判斷
    logic_result = self._logic_verification(sources)
    
    # 第二層：AI 驗證
    try:
        ai_result = await self._ai_verification(information, sources)
    except Exception as e:
        # Fallback：使用邏輯判斷結果
        logger.warning(f"AI 驗證失敗，使用邏輯判斷: {e}")
        ai_result = logic_result
    
    # 第三層：交叉比對
    cross_check = self._cross_reference(sources)
    
    # 綜合結果
    return self._combine_results(logic_result, ai_result, cross_check)
```

   ```python
       if preferences and preferences.get('status') == 'stale':
           stale_days = (datetime.now() - preferences.get('stale_since')).days
           stale_warning = {
               "message": f"您的偏好設定已 {stale_days} 天未更新",
               "suggestion": "是否要更新偏好設定？",
               "actions": ["更新偏好", "繼續使用", "稍後提醒"]
           }
       
       # 建立新會話
       session = await self.create_session(user_id, topic)
       
       return {
           "session_id": session["session_id"],
           "preferences": preferences,
           "stale_warning": stale_warning  # 如果有過時偏好
       }
   ```

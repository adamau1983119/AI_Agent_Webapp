## 🗂️ 主題卡生成邏輯與多語言架構

### 主題卡生成流程

```
┌──────────────────────────────────────────────────────────────────────┐
│                     主題卡生成完整流程                                 │
│                                                                      │
│  ⏰ 排程服務 (SchedulerService v4.1)                                 │
│  │   每 6 小時觸發 (UTC 00:00, 06:00, 12:00, 18:00)                │
│  │                                                                   │
│  ▼                                                                   │
│  📡 主題收集器 (TopicCollector v3.2)                                 │
│  │   1. 角色分配策略 → 從 RSS Feed 收集原始內容                      │
│  │   2. 內容去重 (ContentDeduplicator) → MD5 + 相似度檢測            │
│  │   3. 多樣性評分 (DiversityScorer) → 確保來源多元                  │
│  │   4. 備用關鍵字方案 → RSS 失敗時自動補充                          │
│  │                                                                   │
│  ▼                                                                   │
│  🌐 多語言處理 (display_language + target_language)                  │
│  │   1. 用戶語言偏好 → display_language                              │
│  │   2. 標題翻譯為用戶語言（_translate_title）                       │
│  │   3. 內容生成語言 = target_language（zh-TW/en/ja）                │
│  │                                                                   │
│  ▼                                                                   │
│  💾 儲存到 MongoDB                                                   │
│  │   topics collection → 每個分類 10 筆                              │
│  │                                                                   │
│  ▼                                                                   │
│  🖼️ 自動化工作流 (AutomationWorkflow)                               │
│  │   1. 從 RSS sources[].images 提取預覽圖片                        │
│  │   2. 搜尋匹配圖片 (DuckDuckGo / Google / Unsplash)               │
│  │   3. 階段 1：每個主題 1 張預覽圖                                  │
│  │                                                                   │
│  ▼                                                                   │
│  📱 前端顯示                                                         │
│      Dashboard / Topics → 按用戶語言顯示 titles_i18n[lang]          │
│      TopicDetail → 支援「翻譯全文」按需翻譯                          │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 主題資料模型 (Topic)

```
Topic {
  id: string                    # 唯一識別碼 (topic_{category}_{timestamp}_{index})
  title: string                 # 主題標題（原始語言）
  category: Category            # 分類 (fashion / food / trend)
  status: Status                # 狀態 (pending / confirmed / deleted)
  source: string                # 主要來源名稱
  sources: SourceInfo[]         # 資料來源列表（含原文內容、關鍵字、圖片）
  description: string           # 摘要（約 30 字）
  preview_images: string[]      # 預覽圖片 URL（最多 5 張）
  is_expanded: bool             # 是否已展開完整內容
  generation_config: object     # 生成配置參數

  # 多語言欄位 [已完成 ✅]
  display_language: string      # 生成時的顯示語言 (zh-TW / en / ja)
  original_title: string        # 原始語言標題（翻譯前）
  original_language: string     # 來源原文語言 (en / ja / zh)
  titles_i18n: {                # 多語言標題
    "zh-TW": "繁中標題",
    "en": "English Title",
    "ja": "日本語タイトル"
  }
  description_i18n: {           # 多語言摘要
    "zh-TW": "繁中摘要",
    "en": "English summary",
    "ja": "日本語の概要"
  }

  # 時間戳
  generated_at: datetime
  updated_at: datetime
  created_at: datetime
}
```

### 核心產品理念：「資訊差」策略

```
┌───────────────────────────────────────────────────────────────┐
│                                                               │
│   🌍 全球多語言 RSS 來源                                      │
│   ├── 英文來源：Vogue, WWD, TechCrunch, Eater...             │
│   ├── 日文來源：FASHIONSNAP, 食べログ...                      │
│   └── 中文來源：ELLE HK, 香港01...                           │
│                         ↓                                     │
│   🤖 AI 翻譯 → 標題/摘要 → 用戶語言                         │
│                         ↓                                     │
│   📱 用戶看到：外語內容的「本地化」版本                        │
│                                                               │
│   💡 價值：用戶無需懂外語，即可獲得全球趨勢資訊               │
│   💡 優勢：本地市場尚未報導的國際內容 = 資訊差 = 競爭力       │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### 三大內容類別 × 收集配置

| 類別 | 每次收集 | 每日 4 次 | RSS 來源數 | 主要語言來源 |
|------|:--------:|:---------:|:----------:|:------------:|
| Fashion (時尚) | 10 | 40 | 23+ | en, ja, zh |
| Food (美食) | 10 | 40 | 19+ | en, ja, zh |
| Trend (趨勢) | 10 | 40 | 30+ | en, ja, zh |

## ⚠️ 開發注意事項

### 1. 路由一致性
- Sidebar 的 `path` 必須與 App.tsx 的 Route 定義一致
- 修改路由時需同時更新兩個文件

### 2. 多語言
- 新增 UI 文字時必須同時添加三種語言翻譯
- 避免使用國旗圖示（政治敏感）

### 3. 認證
- `/` 是重定向，不是頁面
- Dashboard 在 `/dashboard`，不是 `/`

### 4. 測試 ID 規範 (data-testid)
- 所有按鈕、連結、輸入框必須添加 `data-testid` 屬性
- 命名格式：`{類型}-{位置}-{功能}`
- 詳細規範請參考：`按鈕測試ID架構表.md`

```typescript
// 類型前綴
btn-     // 按鈕
link-    // 連結
input-   // 輸入框
form-    // 表單
modal-   // 彈窗
menu-    // 選單

// 範例
data-testid="btn-login-submit"
data-testid="link-sidebar-dashboard"
data-testid="input-register-email"
```
